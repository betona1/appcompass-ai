**"AI가 정답을 결정하지 않는다"가 이제 기록으로 남습니다.**

지금까지 시스템은 판단을 제안했지만, 사람이 그 판단에 동의했는지 아닌지가 아무 데도 남지 않았습니다.
Phase 3에서 그 빈칸을 메웁니다.

---

## ⚖ 피벗 승인 워크플로

`G. 피벗 보고서` 화면에 **사람의 결정** 영역이 생겼습니다.

분석이 끝나면 판단이 **검토 대기** 상태로 기록되고, 사람이 **승인** 또는 **거절**해야 합니다.

### 거절할 때는 사유가 필수입니다

승인은 사유가 선택이지만, **거절은 사유 없이 할 수 없습니다.**

> 왜 시스템과 다르게 판단했는지 남지 않으면 나중에 그 판단이 옳았는지 되짚을 수 없습니다.
> 사유 없는 거절은 기록으로서 쓸모가 없습니다.

```
예: "타깃 피벗 대신 문제 정의부터 다시 하기로 함"
    "사내 사정으로 이번 분기는 현재 방향 유지"
```

### 판단 이력

```
07-26 04:10  v1  ● 유지      (신뢰도 1.00, 총점 92.0)  → 검토 대기
07-26 04:10  v1  ■ 판단 보류  (신뢰도 0.20, 총점 80.0)  → 거절함 — 근거를 더 모은 뒤 판단하기로 함
```

그때의 **신뢰도와 총점까지** 함께 남습니다. 이력만 봐도 어떤 상태에서 무슨 결정을 했는지 알 수 있습니다.

### 사람이 내린 결정은 지우지 않습니다

새 분석이 나오면 **아직 검토하지 않은** 판단은 `지난 판단`으로 밀려납니다.
하지만 **이미 승인하거나 거절한 기록은 그대로 남습니다.**

이미 결정한 판단을 두 번 결정할 수도 없습니다. 마음이 바뀌었다면 분석을 다시 실행해야 합니다.

## `① 다음 할 일`도 바뀌었습니다

근거가 충분해지면 **마무리보다 승인을 먼저** 묻습니다.

> **판단을 검토하고 승인하거나 거절하세요: KEEP**
>
> 근거가 판단을 뒷받침하는 상태입니다. 시스템은 제안만 하고 적용하지 않습니다.
> 사람이 확인해야 기록이 남습니다.

거절도 사람의 결정이므로 다음 단계로 넘어갑니다.

## 고친 것

### `유지` 목록의 글자가 잘리던 문제

줄바꿈된 라벨의 둘째 줄이 잘렸습니다.
처음엔 최소 높이를 지정해 때웠는데 그건 한 줄짜리만 고쳐졌고, 여러 줄은 `heightForWidth`가 필요했습니다.

내용이 길면 여전히 넘칠 수 있어 **스크롤 영역**으로 감쌌습니다.
내용을 줄이는 대신 전부 읽을 수 있게 했습니다.

## 업데이트 안내

폴더만 새 것으로 교체하시면 됩니다.
데이터는 `%APPDATA%\AppCompass\appcompass.sqlite3` 에 따로 있어 사라지지 않습니다.
판단 기록 테이블은 실행 시 자동으로 만들어집니다.

> **기존 분석에는 판단 기록이 없습니다.** `분석 실행`을 한 번 다시 누르면 생성됩니다.
