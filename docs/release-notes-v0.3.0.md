**"그래서 지금 뭘 해야 하지"** 에서 막히는 문제를 해결했습니다.
그리고 **이미 만든 MVP**의 다음 단계를 지원합니다.

## ① 다음 할 일 (새 첫 번째 탭)

화면이 아홉 개라 처음 쓰면 막막합니다.
**이제 이 탭만 보시면 됩니다.** 나머지는 그때그때 안내받으면 됩니다.

- 지금 할 일 **하나**만 크게 보여줍니다
- **왜** 그게 지금 중요한지
- **어떻게** 하는지 단계별로
- **그 화면으로 가는 버튼**
- 위에 `6 / 8 단계` 진행률 — 끝이 보여야 막막하지 않습니다

> 할 일을 다섯 개 늘어놓으면 결국 아무것도 안 하게 됩니다.
> 그래서 **한 번에 하나만** 시킵니다.

### 판정 순서

```
프로젝트 없음 → 아이디어 없음 → 필수 항목 빈칸 → 미승인 → 분석 안 함
→ 치명 경고 → 근거 0건 → 신뢰도 부족 → 피벗 권고 → 마무리
```

순서가 중요합니다. 예를 들어 **치명 경고가 근거 등록보다 먼저** 나옵니다.
타깃이 "모든 사람"인 채로 근거를 모아봐야 소용없기 때문입니다.
이 순서는 테스트로 고정되어 있습니다.

피벗 판정별로 다른 안내가 나갑니다.
`TARGET_PIVOT`이면 `D. 타깃 후보`로, `SOLUTION_PIVOT`이면 `B. 구조화 검토`로 보냅니다.

### 모든 탭에서 보입니다

어느 탭에 있든 상단에 `▶ 다음 할 일: …`이 표시됩니다.

## 📖 처음 사용 안내 (F1)

`도움말 → 처음 사용 안내`. 전체 8단계 흐름과, 사람들이 실제로 막히는 세 가지를 정리했습니다.

1. **점수가 낮다고 아이디어가 나쁜 게 아닙니다** — 점수는 "지금 기획서가 얼마나 검증 가능한 형태인가"입니다
2. **HOLD는 오류가 아닙니다** — 근거가 없으면 판단을 확정하지 않는 설계입니다
3. **AI가 아니라 규칙 엔진입니다** — 같은 입력이면 항상 같은 결과, 이유도 항상 표시됩니다

## 📄 개선 명세 (IMPROVEMENT.md)

`TECHSPEC.md`가 "무엇을 만들까"라면, 개선 명세는 **"이미 만들었는데 뭘 고칠까"** 입니다.

### 기능별 구현 상태 (`E. MVP`)

기능마다 **미구현 / 구현 중 / 구현됨 / 제외함**을 표시하고,
`관찰된 문제` 칸에 실제로 겪은 문제를 적습니다. 이 내용이 개선 명세로 넘어갑니다.

구현 상태는 프로젝트에 저장되므로 **분석을 다시 실행해도 유지**됩니다.

### 개선 명세 내용

| 섹션 | 내용 |
|---|---|
| §1 가설 검증 현황 | 5개 가설을 `지지됨 / 반박됨 / 상충 / 근거 부족`으로 판정 |
| §2 유지 | 잘 되는 것 — 건드리면 손해 |
| §3 고칠 것 | **구현된 기능만** ID(C-01…)와 명세 블록 |
| §4 뺄 것 | 반박된 가설에 의존하는 기능 포함 |
| §5 아직 안 만든 기능 | 지금도 필요한지 재검토 |
| §6 다음에 검증할 것 | 구현으로는 답이 안 나오는 것 |
| §7~8 다음 버전 범위 · 완료 정의 | |

**만들지 않은 기능은 개선 대상에 넣지 않습니다.** 만들지도 않은 걸 고치라고 할 수는 없으니까요.

근거가 없거나 행동 데이터가 없으면 문서 앞에 경고가 붙습니다.

## 만들면서 고친 것

### 수익 가설이 잘못 "지지됨"으로 나오던 문제

인터뷰가 `D04 사용자·구매자 구분`만 지지했는데 수익 가설이 검증됐다고 표시됐습니다.
**부모가 구매자라는 사실과 돈을 낼 의사는 다릅니다.**

이제 가설이 여러 항목에 걸쳐 있으면 **전부** 뒷받침돼야 지지로 봅니다.
아니면 "D08에 대한 근거가 없어 확정할 수 없습니다"라고 정확히 말합니다.

이 도구가 하지 말아야 할 **과잉 주장**이라 회귀 테스트로 고정했습니다.

### 그 외

- `유지` 목록에 채점 흔적(`+1 문제 서술 있음 / +1 …`)이 노출되던 것 → 항목명과 점수만
- 안내 문구의 글자 아랫부분이 잘리던 렌더링 버그 (줄바꿈 라벨 세로 정책 누락)
