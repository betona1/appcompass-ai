## 1. 이 프로그램이 하는 일

앱 아이디어를 입력하면 다음을 알려줍니다.

- 지금 이 기획에서 **가장 약한 부분이 어디인지**
- 그 판단의 **근거가 무엇인지**
- **아직 모르는 것**이 무엇인지
- **다음에 무엇을 검증해야 하는지**
- 그래서 **유지할지, 고칠지, 방향을 틀지**

### 이 프로그램이 하지 않는 일

- **사업성을 판정하지 않습니다.** 이 앱이 성공할지 여부는 계산하지 않습니다.
- **근거를 만들지 않습니다.** 인터뷰 결과나 시장 데이터를 지어내지 않습니다.
  등록한 근거만 반영됩니다.
- **대신 결정하지 않습니다.** 모든 판단은 "사람 승인 필요"로 표시됩니다.
- **AI에게 판정을 맡기지 않습니다.** AI는 구조화 초안과 타깃 후보 초안만 만듭니다.
  점수·신뢰도·판단은 전부 규칙 엔진이 계산합니다 ([6장](#6-ai-초안-쓰기-선택)).

> 점수가 낮게 나왔다고 아이디어가 나쁜 게 아닙니다.
> 점수는 **지금 기획서에 적힌 내용이 얼마나 검증 가능한 형태인가**를 나타냅니다.

## 2. 설치와 실행

### 방법 A: 실행파일 (권장)

1. [Releases](../../releases) 에서 `AppCompass-AI-x.y.z-win64.zip` 을 내려받습니다.
2. 압축을 풉니다.
3. `AppCompass.exe` 를 더블클릭합니다.

Python 설치가 필요 없습니다. Windows 10 이상 64비트에서 동작합니다.

> **Windows SmartScreen 경고가 뜨는 경우**
> 코드 서명이 되어 있지 않아 "Windows의 PC 보호" 창이 나올 수 있습니다.
> `추가 정보` → `실행` 을 누르면 됩니다.

### 방법 B: 소스에서 실행

```bash
git clone https://github.com/betona1/appcompass-ai.git
cd appcompass-ai
pip install -r requirements.txt
python run_app.py
```

Python 3.11 이상이 필요합니다.

### 데이터 저장 위치

```
%APPDATA%\AppCompass\appcompass.sqlite3
```

탐색기 주소창에 `%APPDATA%\AppCompass` 를 붙여넣으면 열립니다.

- **백업**: 이 파일 하나만 복사하면 됩니다.
- **초기화**: 이 파일을 삭제하면 처음 상태로 돌아갑니다.
- **위치 변경**: 환경변수 `APPCOMPASS_DB_URL` 을 지정합니다.
  ```
  set APPCOMPASS_DB_URL=sqlite:///D:/내작업/appcompass.sqlite3
  ```

**상단 우측**에 항상 현재 판단과 신뢰도가 표시됩니다.
탭을 어디로 옮겨도 지금 상태를 놓치지 않도록 하기 위해서입니다.

### 상태 표시 규칙

색을 못 보거나 흑백으로 출력해도 구분되도록, 모든 상태는 **기호 + 한글 + 코드**를 함께 씁니다.

| 표시 | 의미 |
|---|---|
| ■ 치명 | 반드시 먼저 해소해야 하는 문제 |
| ▲ 주의 | 보완하면 좋은 문제 |
| · 참고 | 정보 |
| ● 유지 / ● 보완 | 방향을 바꿀 필요 없음 |
| ◆ ○○ 피벗 | 방향 전환 권고 |
| ■ 판단 보류 | 근거 부족으로 확정 불가 |

## 4. 10분 따라하기

> **막막하시면 `① 다음 할 일` 탭만 보세요.**
> 지금 해야 할 일 하나를 알려주고 그 화면으로 데려다줍니다.
> 나머지 탭은 그때그때 안내받으면 됩니다. 아래는 그 안내가 어떤 순서로 나오는지입니다.
>
> 처음 사용 안내는 **F1** 또는 `도움말 → 처음 사용 안내`에서 볼 수 있습니다.

처음 쓰시는 분은 이 순서대로 하시면 전체 흐름을 볼 수 있습니다.

### ① 프로젝트 만들기 (1분)

왼쪽 아래 **새 프로젝트** → 이름을 적고 **도메인**을 고릅니다.

| 도메인 | 언제 고르나 |
|---|---|
| 공통 | 일반적인 앱 아이디어 |
| VibeQuest | 바이브코딩 용어 학습 앱 |
| examath | 초등 뺄셈 받아내림 학습 앱 |

도메인을 고르면 그 분야의 필수 경고, 언노운, MVP 금지 기능이 자동으로 적용됩니다.

### ② 아이디어 적기 (3분) — A 탭

떠오르는 대로 적으세요. **다듬지 않아도 됩니다.**
예상 사용자 칸에 일부러 "수학을 배우는 모든 아이"처럼 넓게 적어보시면
다음 단계에서 프로그램이 어떻게 반응하는지 볼 수 있습니다.

**새 버전으로 저장하고 구조화로 이동** 을 누릅니다.

> 여기 적은 원문은 이후 어떤 경우에도 수정되지 않습니다.

### ③ 구조화하고 승인 (4분) — B 탭

왼쪽 12개 칸을 채웁니다. 오른쪽 위에는 방금 적은 원문이, 아래에는 **경고가 실시간으로** 나타납니다.

경고를 보면서 칸을 고치면 경고가 사라집니다. 치명 경고를 모두 없애는 게 목표지만,
남아 있어도 승인할 수 있습니다(확인 창이 뜹니다).

**승인하고 분석 실행** 을 누릅니다.

> 승인한 버전은 더 이상 수정할 수 없습니다. 내용을 바꾸려면 A 탭에서 새 버전을 만듭니다.
> 이렇게 해야 "언제 무엇이 왜 바뀌었는지"가 남습니다.

### ④ 결과 읽기 (1분) — C 탭

자동으로 이동합니다. **위에서부터** 읽으세요.

```
판단          ← 결론
지금 할 일     ← 당장 무엇을 할지
핵심 위험      ← 먼저 해소할 것
핵심 언노운    ← 아직 모르는 것
경고          ← 상세 지적
평가 점수      ← 참고용 (맨 아래)
```

처음에는 대부분 **■ 판단 보류 (HOLD)** 가 나옵니다. 정상입니다.
등록한 근거가 없어서 판단을 확정할 수 없다는 뜻입니다.
바로 아래에 "근거가 충분했다면 → ◆ 타깃 피벗" 처럼 **잠정 판단**이 함께 표시됩니다.

### ⑤ 근거 등록하고 다시 분석 (1분) — 근거 탭

실제로 한 인터뷰나 관찰을 등록합니다.

- **근거 유형**을 고릅니다 (창업자 가정 0.20 ~ 행동 데이터 1.00)
- 제목과 요약을 적습니다
- **지지하는 평가 항목을 하나 이상 체크**합니다 ← 필수
- **근거 등록**

다시 **분석 실행** 을 누르면 신뢰도가 오르고, 충분해지면 HOLD가 풀립니다.

## 5. 화면별 사용법

### ① 다음 할 일

**처음이시면 이 탭만 보시면 됩니다.**

지금 해야 할 일 **하나**와, 왜 그게 중요한지, 어떻게 하는지, 그리고 그 화면으로 가는 버튼이 있습니다.
위에 `6 / 8 단계` 진행률이 표시되어 어디쯤 왔는지 알 수 있습니다.

할 일을 여러 개 늘어놓지 않는 것은 의도적입니다. 다섯 개를 늘어놓으면 결국 아무것도 안 하게 됩니다.

안내가 나오는 순서:

```
프로젝트 없음 → 아이디어 없음 → 필수 항목 빈칸 → 미승인 → 분석 안 함
→ 치명 경고 → 근거 0건 → 신뢰도 부족 → 피벗 권고 → 마무리
```

**치명 경고가 근거 등록보다 먼저** 나옵니다. 타깃이 "모든 사람"인 채로 근거를 모아봐야 소용없기 때문입니다.

어느 탭에 있든 화면 상단에 `▶ 다음 할 일: …` 이 표시됩니다.

### A. 아이디어 입력

원문을 받는 곳입니다. 판정은 전혀 하지 않습니다.

| 칸 | 설명 |
|---|---|
| 앱 이름 | 가칭도 괜찮습니다 |
| 아이디어 | 한 문단. 다듬지 않아도 됩니다 |
| 예상 사용자 | 지금 떠오르는 대로 |
| 문제 상황 | 사용자가 겪는 문제 |
| 해결 방법 | 어떻게 풀 생각인지 |
| 수익 모델 / 유입 경로 | 모르면 비워둡니다 |
| **변경 사유** | 이번 버전을 만든 이유. H 탭 비교에 쓰입니다 |

저장할 때마다 **항상 새 버전**이 만들어집니다. 이전 버전은 그대로 남습니다.

### B. 구조화 검토

원문을 12개 항목으로 옮기는 곳입니다. **여기가 이 프로그램의 핵심입니다.**

| 칸 | 잘 쓰는 법 |
|---|---|
| 사용자 | 상황 + 문제 + 현재 행동 + 중단 원인. 나이·직업만으로는 부족 |
| 구매자 | 결제 결정자. 같으면 "사용자와 동일" |
| 영향자 | 추천·관리하는 사람 (교사, 팀장) |
| 문제 상황 | **언제, 무엇을 하다가** 문제가 생기는지 |
| 현재 대체 방법 | 지금은 어떻게 넘기는지. "방치"도 답 |
| 대체 방법의 한계 | 시간·복잡성·실패·불안·비용 중 무엇 때문인지 |
| 핵심 행동 | 반드시 완료해야 하는 행동 **하나** |
| 기대 결과 | **몇 % / 몇 분 / 몇 회** 로 측정 가능하게 |
| 첫 성공 경험 | 처음 온 사람이 몇 분 안에 무엇을 해내는지 |
| 재방문 이유 | 내일 다시 열 이유 |
| 수익 모델 | 누가 무엇에 지불하는지 |
| 유입 경로 | 첫 100명을 어디서 데려올지 |

**나쁜 예 → 좋은 예**

```
사용자
✗ 수학을 배우는 아이
○ 초등 2학년 중 두 자리 수 받아내림 문제를 만나면 건너뛰거나
   손가락 세기에서 멈춰 더 이상 시도하지 않는 어린이

기대 결과
✗ 뺄셈을 잘하게 된다
○ 구체물 문제 성공 후 같은 유형 숫자 문제 완료율이 40% 이상으로 오른다
```

### 근거

여기 등록한 것만 신뢰도에 반영됩니다. **프로그램은 근거를 만들지 않습니다.**

| 근거 유형 | 기본 신뢰도 |
|---|---:|
| 창업자 가정 | 0.20 |
| 데스크 리서치 | 0.35 |
| 전문가 검토 | 0.45 |
| 사용자 인터뷰 | 0.50 |
| 프로토타입 테스트 | 0.70 |
| 실제 행동 데이터 | 1.00 |

- **지지 항목**은 반드시 하나 이상 골라야 합니다. 어느 항목의 신뢰도를 올릴지 정하는 것입니다.
- **반박 항목**도 고를 수 있습니다. 지지와 반박이 함께 있으면 신뢰도가 낮아지고 상충 경고가 뜹니다.
- 표본이 3명 미만이면 신뢰도가 추가로 깎입니다.
- 표본이 아무리 커도 **근거 유형의 상한을 넘지 못합니다.**
  창업자 가정은 10만 명을 조사해도 0.20입니다.

#### 처음이라면 — 예시로 양식 채우기

**`예시로 양식 채우기 ▾`** 버튼을 누르면 도메인에 맞는 예시가 뜹니다.
고르면 제목·요약·표본 수·지지 항목 체크까지 한 번에 채워집니다.

> **예시는 근거가 아닙니다.**
> 양식을 어떻게 쓰는지 보여줄 뿐이며, **실제로 관찰하거나 들은 내용으로 바꿔서** 등록해야 합니다.
> 예시 그대로 등록하면 자기 진단을 스스로 속이는 셈이라 판단이 무의미해집니다.

**요약 칸 쓰는 법**

```
✗ 부모들이 힘들어한다              (해석)
○ 5명 중 4명이 '받아내림 숙제에서   (관찰된 사실)
   아이가 연필을 놓는다'고 진술
```

나중에 왜 그렇게 판단했는지 되짚을 수 있어야 하므로, 해석이 아니라 사실을 적습니다.

**불리한 결과도 넣으세요.** 예시 ②·④에는 반박 항목이 미리 체크되어 있습니다.
유리한 근거만 등록하면 신뢰도만 올라가고 판단은 틀어집니다.

#### HOLD를 푸는 데 필요한 근거량

| 등록한 근거 | 전체 신뢰도 | 결과 |
|---|---:|---|
| 없음 | 0.20 | HOLD |
| 창업자 가정만 (몇 건이든) | 0.20 | **HOLD — 절대 안 풀림** |
| 인터뷰 1건, 3개 항목 지지 | 0.31 | HOLD |
| **인터뷰 1건, 5개 항목 지지** | **0.35** | **★ 풀림** |
| 인터뷰 + 프로토타입 테스트 | 0.47 | ★ 풀림 |

창업자 가정은 상한이 0.20이라 아무리 많이 등록해도 HOLD를 풀 수 없습니다.
실제로 누군가에게 물어본 근거가 있어야 합니다.

### C. 자동 진단

10개 평가 항목이 각각 0~5점입니다.

| 코드 | 항목 | 가중치 |
|---|---|---:|
| D01 | 문제 구체성 | 15 |
| D02 | 문제 강도·빈도 | 10 |
| D03 | 타깃 명확성 | 10 |
| D04 | 사용자·구매자 구분 | 5 |
| D05 | 가치 제안 | 10 |
| D06 | 첫 성공 경험 | 10 |
| D07 | 반복 사용 이유 | 10 |
| D08 | 차별성 | 10 |
| D09 | 유입 가능성 | 10 |
| D10 | 구현 가능성 | 10 |

각 줄의 **이유** 칸에 왜 그 점수인지가 적혀 있습니다.

```
+1 문제 상황 서술 있음 / +1 문제 서술이 30자 이상 /
+1 고통 신호(중단·실패·불안 등) 포함 / 상한 3 적용: 문제 발생 트리거가 불명확
```

### D. 타깃 후보

후보를 비교해 **이번 주에 실제로 만날 수 있는** 타깃 하나를 고르는 화면입니다.

- 첫 번째는 항상 "현재 입력된 타깃"입니다.
- 나머지는 도메인 지식에서 나온 후보입니다.
- **근거 신뢰도가 낮으면 추천하지 않고 비교만 제공합니다.** 이건 의도된 동작입니다.

각 후보의 **검증 질문**을 그대로 인터뷰에 쓰시면 됩니다.

### E. MVP

무엇을 만들고 **무엇을 만들지 않을지** 확정하는 화면입니다.

- **P0**: 핵심 문제를 해결하는 기능
- **P1**: 핵심 행동 완료율을 높이는 기능
- **제외**: 이번에 만들지 않을 것 — 도메인별 금지 기능이 자동 추가됩니다

> examath는 광고·가챠·실시간 랭킹이, VibeQuest는 유료 루트박스·실시간 PvP가 자동으로 제외 목록에 들어갑니다.

**측정 이벤트**가 연결되지 않은 기능은 넣지 마세요.

### F. 실험

**"근거를 어떻게 만들지" 막힐 때 여기로 오세요.**

왼쪽에 가설 5개의 검증 현황이, 그 아래에 **검증되지 않은 가설별 추천 실험**이 나옵니다.
절차·성공 기준·목표값·표본 수·예상 비용까지 적혀 있어 그대로 따라 하면 됩니다.

**싼 것부터, 검증 순서대로** 제안합니다. 인터뷰 5건이 프로토타입 개발보다 항상 먼저입니다.
문제 가설이 안 풀렸는데 가격 테스트를 하는 건 순서가 틀립니다.

1. `이 실험 시작하기` → 오른쪽에 실험이 생깁니다
2. 실제로 실행합니다 (인터뷰라면 30분 × 5명)
3. 결과를 입력합니다 — 진행 상태를 '완료'로, 결론을 고릅니다
4. **`근거로 등록하고 재분석`** → 근거가 등록되고 판단이 갱신됩니다

> **근거 유형은 여러분이 고를 수 없습니다.** 실험 유형이 결정합니다.
> 인터뷰는 0.50, 프로토타입은 0.70, 실제 행동 데이터는 1.00입니다.
> 인터뷰를 '행동 데이터'로 등록해 신뢰도를 부풀리는 길을 막아 둔 것입니다.

> **`판단 불가`는 근거가 되지 않습니다.** 표본이나 설계를 보완해 다시 하세요.
> **반박 결론도 그대로 등록됩니다.** 유리한 결과만 넣으면 진단이 무의미해집니다.

### 도메인 진단

기획이 아니라 **콘텐츠 자체**를 봅니다. 도메인에 따라 내용이 다릅니다.
공통 도메인에는 이 기능이 없습니다.

#### examath — 오류 유형 진단

아이가 틀린 문제 하나를 넣으면 어떤 개념이 빠졌는지 분류합니다.
**정답률이 아니라 오류 유형으로 봐야 무엇을 가르칠지 알 수 있습니다.**

| 입력 | 판정 |
|---|---|
| `43 - 7 = 44` | 받아내림의 의미를 이해하지 못함 (자리별로 큰 수−작은 수를 뺌) |
| `43 - 7 = 40` | 받아내림 개념 부재 (일의 자리를 0으로 둠) |
| `43 - 7 = 46` | 십의 자리와 일의 자리 혼동 |
| `52 - 8 = 45` | 뒤로 세기가 어려움 (정답과 1 차이) |
| 무응답 | 틀릴까 봐 시도하지 않음 |

`관찰된 행동` 칸에 손가락을 쓰는지, 구체물로는 되는지 등을 적으면 후보가 좁혀집니다.

#### VibeQuest — 문항 품질 점검

만든 문항이 **정의 암기형인지 실제 상황형인지** 가려냅니다.

```
✗ API란 무엇인가?                        → 단순 정의 암기형 (치명)
○ 배포하려는데 'API key not found' 오류가  → 정의와 실제 상황 연결
   났습니다. 먼저 확인할 것은?
```

정답 해설이 없거나 출처가 없으면 경고합니다.
해설이 없으면 틀렸을 때 배우는 게 없고, 출처가 없으면 AI가 만든 부정확한 문항을 걸러낼 수 없습니다.

> **분류는 확정이 아닙니다.**
> 입력한 내용만 보고 규칙으로 판정한 것입니다.
> 실제 원인은 아이(사용자)를 직접 관찰해야 확인됩니다.
> 패턴이 안 잡히면 지어내지 않고 `분류 불가`로 두고 직접 물어보라고 안내합니다.

### G. 피벗 보고서

- **유지 / 변경 / 삭제** 세 칸으로 할 일이 정리됩니다.
- 보고서는 분석 시점에 **고정**됩니다. 나중에 수정되지 않습니다.
- checksum이 표시되어 파일이 바뀌었는지 확인할 수 있습니다.

#### 사람의 결정 — 승인 / 거절

분석이 끝나면 시스템 판단이 **검토 대기** 상태로 기록됩니다.
**승인**하거나 **거절**해야 다음으로 넘어갑니다.

> 시스템은 판단을 제안할 뿐 적용하지 않습니다.

- **승인** — 사유는 선택
- **거절** — **사유가 필수**입니다

거절 사유를 강제하는 이유는, 왜 시스템과 다르게 판단했는지 남지 않으면
나중에 그 판단이 옳았는지 되짚을 수 없기 때문입니다.

**판단 이력**에는 그때의 신뢰도·총점과 결정 사유가 함께 남습니다.
새 분석이 나오면 검토하지 않은 판단은 `지난 판단`으로 밀려나지만,
**이미 승인·거절한 기록은 그대로 남습니다.**

#### 내보내기 형식 4가지

| 형식 | 언제 쓰나 |
|---|---|
| **진단 보고서 (Markdown)** | 문서로 공유·기록. 깃허브·노션에 그대로 붙여넣기 |
| **진단 보고서 (HTML)** | 브라우저로 보거나 인쇄 |
| **기술 명세 TECHSPEC (Markdown)** | **개발 착수용.** 아래 설명 참고 |
| **작업용 엑셀 (.xlsx)** | 정렬·필터·담당자 배정. 백로그로 옮길 때 |

#### 기술 명세 (TECHSPEC)

진단 결과를 **바로 개발에 넘길 수 있는 기술 명세**로 바꿔 줍니다.
기획과 개발 사이의 빈칸을 메우는 문서입니다.

들어가는 내용:

- 제품 정의와 역할 분리 (사용자·구매자·영향자)
- 이 MVP가 검증할 가설 (H-PROBLEM, H-BEHAVIOR, H-VALUE, H-RETENTION, H-REVENUE)
- **기능마다 ID와 명세 블록** — P0-01, P0-02 … 목적 / 입력 / 출력 / 정상 흐름 / 실패·예외 / 측정 이벤트 / 완료 기준
- 화면 목록과 각 화면이 구현해야 할 상태 (정상·로딩·빈 상태·오류·권한 거부)
- 측정 이벤트 정의표
- 데이터 모델 골격
- 도메인 제약 (협상 대상이 아닌 규칙)
- 위험·언노운·구현 순서·완료의 정의

> **`[결정 필요]` 표시가 핵심입니다.**
> 진단 결과에서 도출할 수 없는 항목은 **지어내지 않고** `[결정 필요]`로 남깁니다.
> 사실처럼 적힌 빈 명세는 빈칸보다 위험하기 때문입니다.
> 이 표시가 하나라도 남아 있으면 구현을 시작하기 전에 사람이 먼저 결정해야 합니다.

AI 코딩 도구에 이 파일을 그대로 넘겨 구현을 맡길 수도 있습니다.
다만 `[결정 필요]`를 먼저 채워야 결과가 쓸 만합니다.

빠르게 확인해보는 방법: `HOLD 임계치` 를 0.05로 낮추고 다시 분석하면 HOLD가 즉시 풀립니다.

## 6. AI 초안 쓰기 (선택)

B 화면의 12칸을 처음부터 채우는 것이 부담스럽다면, AI에게 **초안**을 받을 수 있습니다.

**쓰지 않아도 됩니다.** 키를 넣지 않으면 버튼만 비활성 상태로 남고,
나머지 모든 기능은 지금까지와 똑같이 동작합니다.

### AI가 하는 일 / 하지 않는 일

| 합니다 | 하지 않습니다 |
|---|---|
| 원문을 읽고 12칸 초안 제안 | 점수 계산 |
| 확인이 필요한 것(언노운) 뽑기 | 근거 신뢰도 계산 |
| 다른 각도의 타깃 후보 제안 | 유지·수정·피벗 판단 |
| | 근거 만들기 |
| | 승인 없이 칸 덮어쓰기 |

**판단은 전부 규칙 엔진이 합니다.** AI 초안을 쓴 기획서와 직접 쓴 기획서는
내용이 같다면 점수도 판단도 완전히 같습니다.

### 준비

1. [console.anthropic.com](https://console.anthropic.com) 에서 API 키를 발급받습니다.
2. `AI 도우미` 탭 → `새 키` 칸에 붙여넣고 `저장`.
3. 상단 배너가 초록색 "사용 가능합니다"로 바뀌면 끝입니다.

> **키는 이 PC의 `%APPDATA%\AppCompass\.env` 에 평문으로 저장됩니다.**
> 다른 사람과 함께 쓰는 PC라면 파일 대신 환경변수 `ANTHROPIC_API_KEY` 를 쓰세요.
> 환경변수가 항상 파일보다 우선합니다.
>
> 키는 프로젝트 데이터베이스에 **들어가지 않습니다.** 기획서를 내보내거나
> DB 파일을 백업해도 키가 함께 나가지 않습니다.

### 구조화 초안 받기 — B 탭

1. A 탭에 아이디어를 적고 저장합니다. **원문이 자세할수록 초안이 좋아집니다.**
2. B 탭 위쪽의 `AI로 초안 채우기` 를 누릅니다. (20초 정도 걸립니다)
3. 검토 창이 열립니다.

검토 창에서 봐야 할 것:

| 표시 | 의미 | 어떻게 할지 |
|---|---|---|
| ● 원문에 있음 | 원문에서 그대로 옮긴 것 | 대체로 채택해도 됩니다 |
| ● AI 추측 — 확인 필요 | **원문에 없는 것을 AI가 지어낸 것** | 사실인지 확인하기 전에는 채택하지 마세요 |
| ● 원문에 없음 | AI가 비워 둔 칸 | 직접 채워야 합니다 |

- **체크박스는 전부 해제된 상태로 열립니다.** 읽고 고르라는 뜻입니다.
- `원문에 있는 칸만 선택` 버튼은 추측한 칸을 빼고 골라 줍니다.
- 이미 값을 적어 둔 칸은 **현재값과 초안이 좌우로** 나옵니다. 무엇을 잃는지 보고 결정하세요.
- 채택한 뒤에도 편집 화면에서 자유롭게 고칠 수 있습니다. 아직 승인 전입니다.

> **추측한 칸을 그대로 두면 위험합니다.** 예를 들어 `기대 결과` 에 AI가 써 넣은
> "완료율 40% 향상" 은 근거 없는 숫자입니다. 그대로 두면 이후 모든 진단이
> 그 숫자를 전제로 돌아가고, 보고서에도 사실처럼 실립니다.

### 타깃 후보 초안 받기 — D 탭

분석을 한 번 실행한 뒤, D 탭 아래쪽 `다른 후보 제안받기` 를 누릅니다.

- 위쪽 후보는 규칙 엔진이 만든 것, 아래쪽은 AI 초안입니다. **섞이지 않습니다.**
- AI 후보는 **저장되지 않습니다.** 화면을 옮기면 사라집니다.
  쓸 만하면 B 탭에 직접 옮겨 적으세요.
- AI는 어느 후보가 나은지 순위를 매기지 않습니다. 그건 사람이 정합니다.
- 각 후보의 `검증 질문` 을 실제 사용자에게 물어봐야 비로소 근거가 됩니다.

### 비용

- 초안 버튼을 누를 때만 호출됩니다. 앱을 켜 두는 것만으로는 요금이 들지 않습니다.
- 보내지는 것: 그 버전의 원문(또는 구조화 결과)과 도메인 이름.
- 보내지 **않는** 것: 등록한 근거, 실험 기록, 점수, 다른 프로젝트 내용.
- 요금은 Anthropic 계정으로 청구됩니다. 이 앱은 결제에 관여하지 않습니다.

|---|---|
| 버튼이 회색 | 키가 없거나(→ AI 도우미 탭), 이 버전이 이미 승인됨(→ 새 버전 만들기) |
| "API 키가 올바르지 않습니다 (401)" | 키를 다시 복사해 넣으세요. 앞뒤 공백이 섞이면 실패합니다 |
| "형식 검증을 두 번 통과하지 못해 초안을 버렸습니다" | 원문을 조금 더 구체적으로 적고 다시 시도하거나, 초안 없이 직접 채우세요 |
| "채울 수 있는 칸이 없었습니다" | 원문이 너무 짧습니다. A 탭에 상황을 더 적으세요 |
| 응답이 오래 걸림 | 정상입니다. 20~40초 걸릴 수 있습니다 |

## 7. 판정 규칙 이해하기

### 판단은 위에서부터 순서대로 결정됩니다

```
1. 근거 신뢰도 부족          →  ■ 판단 보류 (HOLD)
2. 문제 구체성·강도 부족      →  ◆ 문제 피벗
3. 타깃이 넓거나 불명확       →  ◆ 타깃 피벗
4. 핵심 행동이 완료되지 않음   →  ◆ 해결책 피벗
5. 재방문 이유가 약함         →  ◆ 재방문 재설계
6. 유입 경로가 약함           →  ◆ 채널 피벗
7. 차별성이 약함             →  ◆ 수익 피벗
8. 큰 문제 없음              →  ● 유지 또는 ● 보완
```

위쪽이 먼저 걸리면 아래는 보지 않습니다.
**문제 정의가 약한데 유입 경로를 고민하는 건 순서가 틀렸기 때문**입니다.

### HOLD가 특별한 이유

근거 신뢰도가 임계치(기본 0.35) 미만이면 **내용이 아무리 좋아도** HOLD입니다.
잘 쓰인 기획서와 검증된 기획서는 다르기 때문입니다.

단, HOLD로 끝내지 않고 "근거가 충분했다면 무엇이었을지"를 함께 보여줍니다.
지금 무엇을 검증해야 할지 알아야 하기 때문입니다.

### 왜 근거가 없으면 신뢰도가 0.20인가

근거가 없는 항목의 신뢰도는 **0.20을 넘을 수 없습니다.**
그래서 근거를 하나도 등록하지 않으면 전체 신뢰도가 0.20이 되고,
기본 임계치 0.35보다 낮으므로 항상 HOLD가 됩니다.

이건 버그가 아니라 설계입니다. "생각만으로 확정된 판단"이 나오지 않게 하려는 것입니다.

### 같은 입력이면 항상 같은 결과

점수·신뢰도·피벗은 **결정론적 규칙**으로 계산됩니다.
같은 입력과 같은 정책 버전이면 언제 실행해도 같은 결과가 나옵니다.
AI 추론은 사용하지 않습니다.

같은 내용으로 다시 분석하면 새 분석을 만들지 않고 기존 결과를 그대로 보여줍니다.
내용이나 근거나 정책이 바뀌어야 새로 실행됩니다.

## 8. 자주 묻는 질문

**Q. 점수가 30점인데 아이디어가 나쁜 건가요?**
아닙니다. 점수는 **지금 기획서에 적힌 내용이 얼마나 검증 가능한 형태인가**를 나타냅니다.
좋은 아이디어도 처음 적으면 낮게 나옵니다. 낮은 항목의 "권장 행동"을 보고 다듬으세요.

**Q. 계속 HOLD만 나옵니다.**
정상입니다. 근거 탭에서 실제 인터뷰나 관찰을 등록하세요.
근거 없이 결과만 보고 싶다면 정책 탭에서 `HOLD 임계치`를 낮출 수 있지만,
그렇게 나온 판단은 검증되지 않은 것임을 기억하세요.

**Q. 승인한 버전을 고치고 싶습니다.**
고칠 수 없습니다. A 탭에서 새 버전을 만드세요.
변경 사유를 적으면 H 탭에서 무엇이 왜 바뀌었는지 추적됩니다.

**Q. 인터넷 연결이 필요한가요?**
아니요. 모든 계산이 로컬에서 이루어집니다. 외부로 데이터를 보내지 않습니다.

**Q. AI가 들어있나요?**
현재 버전에는 없습니다. 모든 판정이 규칙 엔진입니다.
보고서 상단에도 "모델: 사용 안 함 (규칙 엔진 전용)"으로 명시됩니다.

**Q. 우리 회사 도메인을 추가할 수 있나요?**
가능합니다. `src/appcompass/core/domains/` 에 모듈을 만들고 `registry.py`에 등록하면 됩니다.
엔진은 건드리지 않습니다. README의 "도메인 모듈 추가하기" 참고.

**Q. 감사 로그는 어디서 보나요?**
상단 메뉴 **도구 → 감사 로그 보기**. 분석 이벤트도 같은 메뉴에 있습니다.

## 9. 문제 해결

### 실행파일이 안 열립니다

- Windows SmartScreen: `추가 정보` → `실행`
- 백신 차단: 서명되지 않은 PyInstaller 실행파일이라 오탐이 날 수 있습니다.
  걱정되시면 소스에서 직접 실행하세요 (방법 B).
- 첫 실행은 압축 해제 때문에 5~10초 걸릴 수 있습니다.

### 분석 실행 버튼이 회색입니다

구조화 결과를 승인하지 않았습니다. B 탭에서 **승인하고 분석 실행** 을 누르세요.

### 설치가 제대로 됐는지 확인하고 싶습니다

명령 프롬프트에서 실행파일이 있는 폴더로 이동한 뒤:

```
AppCompass.exe --selftest
```

분석을 한 번 돌려 스키마 로딩·채점·판정·보고서 생성을 점검하고
같은 폴더에 `selftest.txt` 를 남깁니다. 마지막 줄이 `RESULT: PASS` 면 정상입니다.

### 분석이 실패했다고 나옵니다

- `FAILED_SCHEMA`: 결과가 형식 검증을 통과하지 못했습니다. 프로그램 버그이니 이슈로 알려주세요.
- `FAILED_INTERNAL`: 예상치 못한 오류입니다. 오류 내용과 함께 이슈로 알려주세요.

어느 경우든 **실패한 결과로는 점수나 판정을 만들지 않습니다.**

### 처음부터 다시 시작하고 싶습니다

`%APPDATA%\AppCompass\appcompass.sqlite3` 파일을 삭제하세요.

### 글자가 깨져 보입니다

Windows에 "맑은 고딕"이 없는 경우입니다. 거의 발생하지 않지만,
`제어판 → 글꼴`에서 맑은 고딕이 설치되어 있는지 확인하세요.
