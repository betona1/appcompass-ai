**순환이 닫혔습니다.**

```text
가설 → 실험 설계 → 실행 → 결과 입력 → 근거로 자동 등록 → 재분석 → 판단 갱신
```

지금까지는 "근거를 등록하세요"까지만 말할 수 있었습니다.
그런데 막막한 건 **무엇을** 검증할지가 아니라 **어떻게** 검증할지였습니다.

## 🧪 F. 실험 (새 화면)

### 가설 검증 현황

5개 가설(`H-PROBLEM` / `H-BEHAVIOR` / `H-VALUE` / `H-RETENTION` / `H-REVENUE`)이
등록된 근거에 따라 `지지됨 / 반박됨 / 상충 / 근거 부족`으로 판정됩니다. 이유도 함께 표시됩니다.

### 추천 실험

검증되지 않은 가설마다 **구체적인 실험**이 제안됩니다. 절차·성공 기준·목표값·표본 수·예상 비용까지.

**examath** 예시:

| 실험 | 유형 | 비용 |
|---|---|---|
| 받아내림 회피 실태 학부모 인터뷰 | 인터뷰 | 30분 × 5명, 개발 없음 |
| 구체물 조작 종이 프로토타입 테스트 | 클릭더미 | 반나절, 개발 불필요 |
| 핵심 행동 후 실제 변화 측정 | 프로토타입 | 며칠~1주 |

**VibeQuest**는 "용어로 막힌 경험 인터뷰", "학습 후 작업 재개율 측정" 등 다른 실험이 나옵니다.

절차는 그대로 따라 할 수 있게 5단계로 적혀 있습니다.

```
1. 초등학교 2학년 학부모 5명을 찾는다.
2. '받아내림 문제에서 아이가 멈춘 적이 있는지' 최근 사례를 묻는다.
3. 최근 한 달에 몇 번 있었는지 횟수를 확인한다.
4. 그때 부모가 실제로 무엇을 했는지 행동을 확인한다.
5. 아이가 스스로 다시 시도한 적이 있는지 묻는다.
```

> **싼 것부터, 검증 순서대로 제안합니다.**
> 문제 가설이 안 풀렸는데 가격 테스트를 하는 건 순서가 틀립니다.
> 인터뷰 5건이 프로토타입 개발보다 항상 먼저입니다.

### 결과 입력과 근거 자동 등록

`이 실험 시작하기` → 실제로 실행 → 결과 입력 → **`근거로 등록하고 재분석`**

한 번 누르면 근거가 등록되고 분석이 다시 돌아 판단이 갱신됩니다.

## 신뢰도를 부풀릴 수 없게 막았습니다

**근거 유형은 실험 유형이 결정합니다.** 사용자가 고를 수 없습니다.

| 실험 유형 | 등록되는 근거 유형 | 신뢰도 |
|---|---|---:|
| 인터뷰 | 사용자 인터뷰 | 0.50 |
| 클릭더미 · 프로토타입 · 컨시어지 | 프로토타입 테스트 | 0.70 |
| 랜딩페이지 · MVP출시 · 가격 · 재방문 테스트 | 실제 행동 데이터 | 1.00 |

인터뷰를 '행동 데이터'로 등록해 신뢰도를 올리는 길을 없앴습니다.

**`판단 불가`는 근거가 되지 않습니다.** 표본이나 설계가 부족했다는 뜻이므로 보완해 다시 하라고 안내합니다.

**반박 결론은 반박 근거로 등록됩니다.** 불리한 결과도 그대로 반영되어 신뢰도가 낮아지고 상충 경고가 뜹니다.

**근거로 등록한 실험은 잠깁니다.** 나중에 결과를 바꾸면 등록된 근거와 어긋나기 때문입니다.

## 실제로 도는 것을 확인했습니다

```text
① 초기 판단: HOLD, 신뢰도 0.20
② 추천 실험 3개 (H-PROBLEM, H-BEHAVIOR, H-VALUE)
③ 학부모 인터뷰 실험 시작 (절차 5단계)
④ 결과 입력: 5명 중 4명이 월 2회 이상 (80%)
⑤ 근거 자동 등록: USER_INTERVIEW, 신뢰도 0.50, D01·D02 지지
⑥ 재분석: 신뢰도 0.20 → 0.275
⑦ H-PROBLEM: 근거 부족 → 지지됨
```

---

## `① 다음 할 일`도 연결됐습니다

HOLD 상태에서 이제 **`F. 실험으로 가기`** 로 보냅니다.

> 'F. 실험' 화면에 검증되지 않은 가설별로 구체적인 실험이 제안돼 있습니다.
> 가장 위 실험(대개 인터뷰 5명, 30분)을 '이 실험 시작하기'로 시작합니다.
