진단 결과를 **바로 개발에 넘길 수 있는 형태**로 내보냅니다.
진단만 하고 끝나는 게 아니라, 기획과 개발 사이의 빈칸을 메우는 것이 이번 버전의 목표입니다.

```text
아이디어 → 구조화 → 진단 → MVP 확정 → TECHSPEC.md → 구현
                                     └→ 엑셀 백로그 → 담당자 배정
```

## 새로 추가된 것

### 📄 기술 명세 (TECHSPEC.md) 생성

`G. 피벗 보고서` 화면에서 **기술 명세 TECHSPEC (Markdown)** 을 골라 내보냅니다.
진단 결과가 개발 착수 가능한 명세로 바뀝니다.

**기능마다 ID와 명세 블록이 붙습니다.**

```markdown
#### P0-01 핵심 행동: 화면의 구체물을 직접 쪼개고 옮겨 10을 만들어 받아내림 한 문제를 해결한다

| 항목 | 내용 |
|---|---|
| 목적 | [결정 필요] |
| 검증하는 가설 | H-VALUE |
| 입력 | [결정 필요] |
| 출력 | [결정 필요] |
| 정상 흐름 | [결정 필요] |
| 실패·예외 | [결정 필요] |
| 측정 이벤트 | `manipulative_action_complete`, `concrete_problem_complete` |
| 완료 기준 | [결정 필요] |
```

포함되는 내용:

- 제품 정의와 역할 분리 (사용자 · 구매자 · 영향자)
- 검증할 가설 5종 (H-PROBLEM / H-BEHAVIOR / H-VALUE / H-RETENTION / H-REVENUE)
- P0 · P1 기능별 명세 블록, **이번에 만들지 않을 것** 목록
- 화면 목록과 각 화면이 구현해야 할 상태 (정상 · 로딩 · 빈 상태 · 오류 · 권한 거부)
- 측정 이벤트 정의표, 데이터 모델 골격
- **도메인 제약** — examath는 "구체물 → 그림 → 숫자 순서를 건너뛰지 않는다",
  VibeQuest는 "사용자의 프로젝트 코드를 저장하지 않는다" 같은 규칙이 명세에 박힙니다
- 위험 · 언노운 · 구현 순서 · 완료의 정의

> **`[결정 필요]` 표시가 이 기능의 핵심입니다.**
>
> 진단 결과에서 도출할 수 없는 항목은 **지어내지 않고** `[결정 필요]`로 남깁니다.
> 그럴듯하게 채워진 명세는 빈칸보다 위험합니다. 아무도 그게 추측인 줄 모르니까요.
> 이 표시가 남아 있으면 구현 전에 사람이 먼저 결정해야 합니다.

기획 판단이 `HOLD`거나 피벗 권고 상태면 명세 맨 앞에 **구현 착수 전 경고**가 붙습니다.

AI 코딩 도구에 이 파일을 그대로 넘겨 구현을 맡길 수도 있습니다.

### 📊 작업용 엑셀 (.xlsx) 내보내기

읽기용 문서와 달리 **작업용**입니다. 정렬·필터하고 담당자를 배정하라고 만들었습니다.
시트를 목적별로 나눴습니다. 한 시트에 다 넣으면 아무 것도 못 하니까요.

| 시트 | 내용 | 비어 있는 칸 (직접 채우세요) |
|---|---|---|
| 요약 | 총점 · 신뢰도 · 판단 · 엔진/정책 버전 | — |
| 평가 점수 | 10개 항목, 점수 이유, 부족한 근거 | — |
| 경고 | 심각도 · 코드 · 권장 행동 | — |
| 할 일 | 다음 행동 · 유지 · 변경 · 삭제 · 언노운 | 담당, 기한 |
| 타깃 후보 | 후보별 사용자 · 구매자 · 위험 · 검증 질문 | — |
| MVP 백로그 | P0/P1/제외 기능에 ID 부여 | 담당, 예상 규모, 완료 기준 |
| MVP 가설·흐름 | 가설, 사용자 흐름, 위험 | — |
| 측정 이벤트 | 이벤트 목록 | 발생 시점, 필수 속성, 구현 여부 |
| 근거 | 등록된 근거 전체 | — |

2점 이하 항목은 빨간색으로 표시되고, 점수 시트에는 합계 수식이 들어갑니다.

## 내보내기 형식 정리

`G. 피벗 보고서` 화면에서 4가지 중 고릅니다.

| 형식 | 언제 |
|---|---|
| 진단 보고서 (Markdown) | 문서 공유·기록 |
| 진단 보고서 (HTML) | 브라우저로 보거나 인쇄 |
| **기술 명세 TECHSPEC (Markdown)** | **개발 착수** |
| **작업용 엑셀 (.xlsx)** | **백로그·담당자 배정** |

## 업데이트 안내

기존 분석에는 TECHSPEC이 없습니다. `분석 실행`을 한 번 다시 누르면 생성됩니다.
데이터는 그대로 유지됩니다.

소스로 쓰시는 분은 의존성이 하나 늘었습니다.

```bash
pip install -r requirements.txt   # openpyxl 추가
```
