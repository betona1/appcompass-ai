"수정이 안 된다", "판단 보류가 왜 뜨는지 모르겠다" — 실제 사용 중 나온 두 가지 문제를 고쳤습니다.
둘 다 기능이 없어서가 아니라 **왜 막혔는지 알려주지 않아서** 생긴 문제였습니다.

---

## 고친 것

### 🔓 승인된 버전에서 구조화 결과를 고칠 수 없던 문제

**증상**
`B. 구조화 검토`에서 `첫 성공 경험`을 고치려는데 입력이 되지 않았습니다.

**원인**
승인된 버전은 잠깁니다. 무엇이 언제 왜 바뀌었는지 추적하기 위한 의도된 규칙입니다.

문제는 그 다음이었습니다. **`첫 성공 경험`·`구매자`·`영향자`·`재방문 이유`·`대체 방법의 한계`는
B화면에만 있고 A화면에는 없습니다.** 그래서 승인 후 이 값들을 고치려면
A화면에서 관계없는 원문을 다시 저장하는 우회로밖에 없었습니다 — 사실상 수정 경로가 막혀 있었습니다.
게다가 잠긴 입력칸이 평소와 똑같이 생겨서 그냥 고장 난 것처럼 보였습니다.

**수정**

- B화면에 **`이 내용으로 새 버전 만들어 수정하기`** 버튼 추가 (승인된 버전에서만 표시)
  누르면 변경 사유를 묻고, 지금 화면 내용 그대로 새 버전을 만들어 즉시 편집 가능해집니다.
  원문은 그대로 물려받으므로 A화면을 거칠 필요가 없습니다.
- 잠긴 필드를 **회색 배경 + 점선 테두리**로 구분
- 배너에 왜 잠겼는지와 어떻게 푸는지를 함께 안내

### ❓ 판단 보류(HOLD)가 왜 뜨는지 알 수 없던 문제

HOLD는 **등록된 근거가 0건**일 때 나옵니다.

```
근거 0건  →  각 항목 신뢰도 0.20 상한  →  전체 0.20 < 기준 0.35  →  HOLD
```

오류가 아니라 "생각만으로 확정된 판단"이 나오지 않게 막는 설계입니다.
기획서를 잘 쓴 것과 검증된 것은 다르니까요.

그런데 화면에는 결과만 나오고 이유가 없어 고장으로 보였습니다.

**수정** — `C. 자동 진단` 화면 판단 영역에 원인과 해결 경로를 바로 붙였습니다.

- 왜 HOLD인지 (근거 0건 → 신뢰도 상한 → 기준 미달)
- 근거가 충분했다면 어떤 판단이었을지
- **`근거 등록하러 가기`** 버튼 (근거 탭으로 바로 이동)
- 근거 없이 결과만 보려면 정책 탭에서 임계치를 낮출 수 있다는 것과, 그 판단은 검증된 게 아니라는 것

## 새로 추가된 것

### ✳ 필수 입력 항목

필수 항목이 비면 **승인 버튼이 잠기고**, 무엇이 왜 필요한지 알려줍니다.
채우면 즉시 풀립니다. A화면·B화면 모두 **빨간 별표(*)** 로 표시됩니다.

| 구분 | 항목 |
|---|---|
| **필수** | 사용자, 문제 상황, 핵심 행동, 기대 결과 |
| **필수 (examath 전용)** | + 구매자 — 아이가 쓰고 부모가 결제하므로 |
| 경고만 | 영향자, 현재 대체 방법, 첫 성공 경험, 재방문 이유, 유입 경로 등 |

> **모든 항목을 강제하지 않은 이유**
>
> 이 도구의 목적은 빈칸을 **발견하게 하는 것**입니다. 전부 강제하면 진단 자체가 무의미해지고,
> 초안 단계의 아이디어를 기록조차 할 수 없게 됩니다.
> 그래서 **분석이 성립조차 안 되는 최소 항목만** 필수로 했습니다.
> 나머지 빈칸은 경고와 점수로 드러납니다.

**도메인마다 필수 항목이 다릅니다.** examath는 구매자가 필수지만 VibeQuest는 아닙니다.
`required_fields()`를 도메인 모듈이 선언하는 구조라, 새 도메인을 추가할 때 엔진을 건드리지 않습니다.
